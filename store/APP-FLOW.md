# NasDSH 工作台 — 应用主流程说明

> 应用：NasDSH 工作台（`com.firewell.nasdsh`）· 版本 0.1.0.0003 · 更新日期 2026-11-06
> 形态：UGOS Pro Docker 应用（amd64 / nasync），端口 12704

## 1. 应用定位

NasDSH 是运行在用户自有 NAS 上的 **DeepSeek Harness（dsh）工作台外壳**：

- 内置 dsh `0.2.1-rc.5` 与 dsh-TUI `0.18.0`（均为 MIT，未修改上游源码）；
- 一种应用提供两种用法：**共享 Web 工作台**（一个 dsh web 实例）与
  **每项目一个 CLI 终端**（tmux + dsh-TUI）；
- 模型服务商与 API Key 全部由用户自行配置，安装包内**不含任何预置凭据**；
- 无开发者服务器，不收集用户数据（详见 `PRIVACY.md`）。

## 2. 安装与启动

1. 应用中心「手动安装」选择 `.upk`，按提示填写安装参数：
   - `PATH`（项目目录，可多个）：按原路径挂载进容器；
   - `DATA_PATH`（数据目录，建议 SSD 卷）：dsh profile、凭据、会话、日志；
   - `TERMINAL_PIN`（可选）：访问口令，留空则不启用鉴权。
2. 安装完成后点击桌面图标（或浏览器访问 `http://<NAS-IP>:12704`）；
3. 容器以 root 启动 → 校正 `DATA_PATH` 属主 → `setpriv` 降权到 `1000:10` 运行
   `sessiond`；`restart: always`，随 NAS 开机自启；
4. 首次启动把镜像内的 dsh profile 模板播种到 `DATA_PATH`，**已有文件绝不覆盖**。

## 3. 主流程

### 3.1 首次启动（合规）

```
打开页面 → 隐私政策全文弹窗 →「同意并使用」→ 进入工作台
                              └─「不同意」→ 离开（about:blank）
```

- 弹窗正文与仓库 `PRIVACY.md` **同一份文件**（镜像内 `/srv/www/docs/privacy.md`），
  中英双语，按业务功能逐项披露；
- 页脚常驻「隐私政策 / 用户协议 / 许可协议 / 技术支持」，任何界面随时可打开全文；
- 语言默认跟随浏览器，页脚可切换 简体中文 / English（含终端提示与全部对话框）。

### 3.2 Web 工作台（默认）

```
＋新建 → 类型选 WEB → 打开 Web 工作台
   → 容器内拉起唯一一个 dsh web 进程（127.0.0.1:随机端口）
   → sessiond 以 /w/ 前缀反代（HTTP + WebSocket）
   → 浏览器内是完整 dsh 图形界面；项目在 dsh 侧栏 Workspaces 里添加/切换
```

- 共享实例只启动一次，内存占用更低；
- 关掉 tab 后进程保留，重开 tab 即恢复；
- 「会话」面板可重启（`/api/web/restart`）或结束（`/api/web/stop`）该实例。

### 3.3 CLI 终端

```
＋新建 → 类型选 CLI → 填写 tab 名称 → 目录浏览器选项目目录 → 创建
   → sessiond 建 tmux 会话（`tmux new -A -s <name>`），会话内运行 dsh-TUI
   → 浏览器 xterm.js ↔ WebSocket ↔ PTY ↔ tmux
```

- 关窗/断网只断开连接，tmux 会话继续；重开 tab 自动续连并回放最近输出；
- 输入 `exit` 或在「会话」面板点「结束」才会终止会话；
- 同一项目目录可被多个 tab 使用。

### 3.4 会话保持与恢复

- 页面把打开的 tab 记在浏览器 `localStorage`；重新打开时按记录重建 tab；
- 后端重启（应用升级/设备重启）后，tmux 会话与 dsh 会话记录仍在
  `DATA_PATH`，重开即续（设备重启按产品语义清空运行中的 tmux 会话）。

### 3.5 访问口令（可选）

- 安装时设置 `TERMINAL_PIN`：entrypoint 写入 `DATA_PATH/.term_pin`（0600）后
  **立即 `unset` 环境变量**，服务进程环境里不再有明文口令；
- 登录为**挑战-应答**：`GET /api/pin-challenge` 取一次性 nonce，浏览器计算
  `sha256(nonce + sha256(PIN))` 提交；明文口令不出浏览器、不进 URL、不写日志；
- 成功后签发服务端随机 token，经 `HttpOnly + SameSite=Strict` Cookie 携带，
  WebSocket 握手自动带上；失败限速。

### 3.6 升级 dsh / dsh-TUI

- 页头「⬆ 升级 dsh」或终端 `nasdsh-update`：容器内用 pnpm/npm 安装最新版；
- 升级写入数据卷持久层，重启后新会话使用新版本；不污染 NAS 系统环境。

## 4. AI 功能定位与合规说明

1. **本应用不提供生成式人工智能服务**：不内置模型、不代理、不中转、不转售
   任何模型能力，也不面向公众提供生成内容。
2. AI 能力来自**用户自行配置**的第三方模型服务商（如 DeepSeek、智谱 BigModel、
   阿里云百炼、火山引擎等，均由服务商按国家要求完成备案）。用户需自行在 dsh
   界面填入自己的 API Key，费用与条款由用户与服务商约定。
3. 应用本身无账号体系、无内容发布、无社交、无支付、无广告，不申请相机、
   通讯录、位置、麦克风、短信等任何设备权限。
4. 与 DeepSeek 官方**无隶属或合作关系**；“DeepSeek / DeepSeek Harness / dsh”
   为 DeepSeek 项目品牌，MIT 许可不含商标授权；应用名称与简介已注明
   “内置 DeepSeek Harness”。

## 5. 异常场景

| 场景 | 行为 |
|---|---|
| 网络中断 / 页面刷新 | WebSocket 自动重连（最多 6 次），终端回放最近输出 |
| `DATA_PATH` 未挂载独立卷 | 启动日志打印明确警告（不会静默丢数据）；仍可运行 |
| `DATA_PATH` 属主异常（root） | 启动时自动 `chown` 到 1000:10 后降权 |
| 模型 Key 未配置 / 填错 | dsh 内提示鉴权失败；不影响工作台与其他会话 |
| dsh web 进程退出 | 「会话」面板显示已停止，点「打开」自动重启 |
| 升级失败（无网络/镜像源不可达） | 返回失败原因，现有版本继续可用 |
| 设备重启 | 应用随系统自启；tmux 会话清空（产品语义），会话记录保留 |
| 口令输错 | 返回「口令不对」，同一 nonce 失效，需重新取挑战值 |

## 6. 数据与权限

- 挂载：项目目录（用户指定，按原路径挂载，仅作工作目录）、数据目录
  （`DATA_PATH`，存 profile/凭据/会话/日志/口令）；
- 不写入、不删除挂载目录中与本应用无关的数据；
- 容器内以非 root（1000:10）运行应用进程，不申请特权，不修改 NAS 系统文件；
- 端口：容器 8080 → 宿主 12704（>1024）。
